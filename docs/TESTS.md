# Тесты приложения

Документ описывает автоматические тесты Workspace Calendar версии 1.9.0.

Актуальное состояние на 16 августа 2026 года:

- 24 тестовых файла;
- 99 тест-кейсов;
- тестовый раннер — Vitest;
- браузерное окружение для тестов хранилищ и компонентов — jsdom.

## Команды запуска

Запустить все тесты один раз:

```bash
npm test
```

Запустить тесты в режиме наблюдения:

```bash
npm run test:watch
```

Запустить отдельный тестовый файл:

```bash
npm test -- src/app/stores/auth.store.test.js
```

После изменений в общей логике рекомендуется дополнительно проверить production-сборку:

```bash
npm run build
```

## Авторизация — 13 тестов

### `src/app/stores/auth.store.test.js` — 6 тестов

Проверяет основную логику авторизации и регистрации с замоканным Supabase API:

1. Нормализация email: удаление пробелов и перевод в нижний регистр.
2. Локализация ошибки при неверном email или пароле.
3. Блокировка отправки некорректной регистрации на сервер:
   - пустое имя;
   - некорректный email;
   - пароль короче шести символов.
4. Создание локальной сессии и профиля после успешного входа.
5. Немедленный выход деактивированного пользователя и сохранение данных для окна блокировки.
6. Понятное русское сообщение при обрыве соединения.
7. Сценарий регистрации, требующий подтверждения email.

> Нормализация email и локализация ошибки проверяются одним тестом. Три варианта некорректной регистрации также объединены в один тест, поэтому Vitest учитывает файл как 6 тестов.

### `src/app/utils/errors/authErrorMessage.test.js` — 7 тестов

Проверяет единый перевод ошибок Supabase:

1. `invalid_credentials` — неверный email или пароль.
2. `email_not_confirmed` — email ещё не подтверждён.
3. `user_already_exists` — аккаунт уже существует.
4. `weak_password` — слишком простой пароль.
5. `over_email_send_rate_limit` — превышен лимит писем.
6. Распознавание старого ответа Supabase без поля `code`.
7. Защита интерфейса от вывода сырого, неизвестного или повреждённого сообщения сервера.

## Календарь и события — 32 теста

### `src/app/stores/calendar.store.test.js` — 12 тестов

## Правила обновления документа

При добавлении, удалении или изменении тестов необходимо:

1. Обновить описание соответствующего раздела.
2. Обновить количество тестов в заголовке раздела и сводной таблице.
3. Запустить `npm test` и сверить итоговые значения Vitest.
4. Если тест защищает от конкретной регрессии, описать пользовательский сценарий, а не только название функции.
