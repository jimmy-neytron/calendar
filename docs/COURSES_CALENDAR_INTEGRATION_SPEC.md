# Техническое задание: интеграция Courses с календарём

## 1. Назначение документа

Документ описывает изменения только в приложении календаря для подключения внешнего приложения [Courses](https://github.com/jimmy-neytron/courses), получения доступных пользователю курсов и создания расписания занятий.

Интеграция на стороне Courses должна оставаться простой: персональный токен и два read-only API-метода. Полноценный OAuth, двусторонняя синхронизация прогресса и автоматическое обновление версии курса не входят в первый релиз.

## 2. Цель

Пользователь должен иметь возможность:

1. Подключить свой аккаунт Courses к календарю.
2. Получить список доступных ему курсов.
3. Выбрать курс и опубликованную версию программы.
4. Выбрать дни недели, время и дату начала занятий.
5. Увидеть предварительное расписание всех уроков.
6. Создать отдельное событие календаря для каждого урока.
7. Открывать соответствующий урок Courses из события календаря.
8. Переносить или удалять отдельные занятия без повреждения всего учебного плана.

## 3. Границы ответственности

### Courses отвечает за

- курсы, модули, уроки и учебные блоки;
- опубликованные версии курсов;
- порядок и продолжительность уроков;
- доступ пользователя к курсу;
- прохождение уроков;
- ссылку для открытия урока.

### Календарь отвечает за

- подключение интеграции;
- выбор курса;
- настройки учебного расписания;
- вычисление дат занятий;
- создание и изменение событий;
- напоминания;
- хранение связи между уроком и событием;
- отображение учебного плана.

### Запрещено

- читать таблицы Supabase проекта Courses напрямую из браузера календаря;
- передавать `service_role` одного проекта другому;
- связывать пользователей только по email;
- хранить токен Courses в `localStorage`;
- формировать десятки событий отдельными клиентскими запросами без транзакции;
- автоматически менять опубликованный учебный план при изменении курса автором.

## 4. Термины

- **Подключение** — сохранённая связь аккаунта календаря с аккаунтом Courses.
- **Manifest** — read-only снимок опубликованной версии курса, необходимый для построения расписания.
- **Учебный план** — настройки расписания одного курса в календаре.
- **Учебная сессия** — один запланированный урок.
- **Связанное событие** — событие `events`, созданное для учебной сессии.
- **Закреплённая версия** — `course_release`, выбранный при создании плана.

## 5. Предпосылки

В Courses уже существуют:

- `courses.current_release_id`;
- `course_releases.snapshot`;
- `course_modules.position`;
- `lessons.position`;
- `lessons.duration_minutes`;
- `courses.default_lesson_duration`;
- `lesson_progress`.

В календаре уже существуют:

- раздел интеграций;
- таблица `events`;
- `events.linked_entity_type`;
- `events.linked_entity_id`;
- механизм изменения связанных событий;
- рабочие пространства и коллекции календарей;
- напоминания;
- тарифный признак `integrations`.

Дата завершения учебного плана должна вычисляться по фактическому количеству уроков в manifest. Поля `duration_weeks` и `lessons_per_week` используются только как подсказка.

## 6. Простой контракт с Courses

### 6.1. Подключение

В настройках Courses пользователь создаёт персональный токен интеграции с правами:

```text
courses:read
progress:read
```

Для MVP обязательным является только `courses:read`.

В календаре пользователь вставляет токен. Адрес Courses задаётся конфигурацией серверной Edge Function и не вводится пользователем.

Все обращения к Courses выполняются Edge Function календаря:

```text
Браузер календаря
  -> Supabase Edge Function календаря
  -> API Courses
```

### 6.2. Проверка токена и список курсов

```http
GET /integration/v1/courses
Authorization: Bearer <personal-token>
Accept: application/json
```

Успешный ответ:

```json
{
  "user": {
    "id": "uuid",
    "displayName": "Иван"
  },
  "courses": [
    {
      "id": "uuid",
      "releaseId": "uuid",
      "title": "Английский A2",
      "description": "Базовый курс",
      "coverUrl": "https://...",
      "accentColor": "#00DC82",
      "lessonCount": 18,
      "durationWeeks": 6,
      "lessonsPerWeek": 3,
      "defaultLessonDuration": 45,
      "status": "active",
      "updatedAt": "2026-07-29T12:00:00Z"
    }
  ]
}
```

Courses возвращает только те курсы, которые пользователь имеет право проходить. Черновики и неопубликованные версии не возвращаются.

### 6.3. Получение manifest

```http
GET /integration/v1/courses/{courseId}/manifest?releaseId={releaseId}
Authorization: Bearer <personal-token>
Accept: application/json
```

Успешный ответ:

```json
{
  "schemaVersion": 1,
  "course": {
    "id": "uuid",
    "releaseId": "uuid",
    "releaseVersion": 3,
    "title": "Английский A2",
    "coverUrl": "https://...",
    "accentColor": "#00DC82",
    "defaultLessonDuration": 45
  },
  "lessons": [
    {
      "id": "uuid",
      "moduleId": "uuid",
      "moduleTitle": "Знакомство",
      "modulePosition": 0,
      "title": "Первый диалог",
      "lessonPosition": 0,
      "durationMinutes": 45,
      "url": "https://courses.example/preview/lessons/uuid"
    }
  ]
}
```

Требования к manifest:

- `lessons` содержит только опубликованные уроки;
- уроки отсортированы либо содержат позиции для сортировки;
- `durationMinutes` является положительным целым числом;
- `url` ведёт на доступный пользователю урок;
- версия manifest не изменяется задним числом;
- пустой список уроков считается ошибкой планирования.

### 6.4. Ошибки API

Courses использует стандартные статусы:

- `401` — токен неверный или отозван;
- `403` — нет доступа к курсу;
- `404` — курс или release не найден;
- `409` — release больше недоступен;
- `429` — превышен лимит;
- `5xx` — временная ошибка Courses.

Ответ с ошибкой:

```json
{
  "error": {
    "code": "COURSE_NOT_FOUND",
    "message": "Курс не найден"
  }
}
```

## 7. Пользовательский сценарий

### 7.1. Карточка интеграции

В `/integrations` добавить карточку:

```text
Курсы
Планируй прохождение курсов в календаре
```

Состояния карточки:

- не подключено;
- подключено;
- требуется переподключение;
- временная ошибка;
- недоступно по тарифу.

Нажатие открывает `/integrations/courses`.

### 7.2. Экран неподключённой интеграции

Экран содержит:

- короткое объяснение результата;
- поле персонального токена;
- ссылку «Где получить токен»;
- кнопку «Подключить»;
- состояние проверки;
- понятное сообщение об ошибке.

После успешной проверки токен очищается из формы и больше не отображается.

### 7.3. Экран подключённой интеграции

Показываются:

- имя пользователя Courses;
- состояние подключения;
- время последной успешной проверки;
- активные учебные планы;
- кнопка «Запланировать курс»;
- кнопка обновления списка;
- действие переподключения;
- действие отключения.

### 7.4. Мастер планирования

Использовать большую модалку с тремя обязательными шагами. Переход вперёд невозможен, пока текущий шаг невалиден.

#### Шаг 1. Курс

- загрузить курсы через Edge Function;
- показать обложку, название, количество уроков и примерную длительность;
- выбрать ровно один курс;
- загрузить manifest выбранного release;
- запретить продолжение при ошибке или пустом manifest.

#### Шаг 2. Расписание

Обязательные поля:

- дата начала;
- минимум один день недели;
- время для каждого выбранного дня;
- календарная коллекция;
- часовой пояс;
- напоминание.

Дополнительные поля:

- участники события;
- ответственный;
- исключённые даты;
- учитывать уже занятое время.

Значения по умолчанию:

- дата начала — сегодня или ближайшая будущая дата;
- дни недели — на основе `lessonsPerWeek`, но не выбирать их без подтверждения пользователя;
- время — последнее использованное время или `19:00`;
- продолжительность — из каждого урока;
- напоминание — `1h`;
- ответственный — текущий пользователь.

Если число выбранных дней отличается от `lessonsPerWeek`, показать информационное предупреждение. Это не блокирует продолжение.

#### Шаг 3. Проверка

Показать:

- название курса;
- количество занятий;
- первую и последнюю дату;
- общую учебную продолжительность;
- список всех занятий;
- обнаруженные конфликты;
- исключённые даты;
- календарную коллекцию.

Пользователь может:

- вернуться к расписанию;
- исключить отдельную дату;
- изменить время отдельного занятия;
- подтвердить создание.

После подтверждения кнопка блокируется до завершения операции. Повторное нажатие не должно создавать дубликаты.

## 8. Алгоритм построения расписания

### 8.1. Входные данные

```ts
interface CourseScheduleInput {
  startDate: string
  timezone: string
  weekdayTimes: Array<{
    weekday: 1 | 2 | 3 | 4 | 5 | 6 | 7
    startTime: string
  }>
  excludedDates: string[]
}
```

ISO weekday:

- `1` — понедельник;
- `7` — воскресенье.

### 8.2. Порядок уроков

Уроки сортируются по:

1. `modulePosition`;
2. `lessonPosition`;
3. исходному индексу manifest как стабильному fallback.

### 8.3. Распределение

1. Начать с `startDate`, включая эту дату.
2. Идти по календарным дням вперёд.
3. Если weekday выбран и дата не исключена, назначить следующий урок.
4. На одну выбранную дату назначать один урок.
5. Продолжать, пока не закончатся уроки.
6. Конечная дата равна дате последнего назначенного урока.

Праздники и выходные автоматически не исключаются. Пользователь явно выбирает нужные дни недели.

### 8.4. Время окончания

```text
endTime = startTime + durationMinutes
```

Событие не должно переходить через полночь, потому что текущая модель `events` хранит одну дату. Если урок не помещается до `23:59`, мастер требует выбрать более раннее время.

### 8.5. Конфликты

Конфликтом считается пересечение с существующим событием текущего workspace и выбранных участников.

Конфликт:

- отображается в preview;
- не запрещает создание;
- требует визуального подтверждения;
- не переносит занятие автоматически в MVP.

### 8.6. Идемпотентность

Перед подтверждением клиент создаёт `idempotencyKey`. Повторная отправка того же ключа возвращает ранее созданный план.

Уникальность учебной сессии:

```text
(plan_id, external_lesson_id)
```

Уникальность события курса:

```text
events(linked_entity_type, linked_entity_id)
where linked_entity_type = 'course-lesson'
```

## 9. Модель данных календаря

Названия миграций должны соответствовать текущей последовательности проекта.

### 9.1. `course_integrations`

```text
id uuid primary key
user_id uuid not null
workspace_id text not null
external_user_id text
external_display_name text
status text not null
last_checked_at timestamptz
last_error text
created_at timestamptz
updated_at timestamptz
```

Ограничения:

- один активный connection пользователя на workspace;
- `status`: `active`, `invalid`, `error`, `disconnected`;
- таблица не содержит открытый токен.

### 9.2. `course_integration_credentials`

```text
integration_id uuid primary key
token_ciphertext text not null
token_iv text not null
created_at timestamptz
updated_at timestamptz
```

Требования:

- запретить доступ `anon` и `authenticated`;
- доступ только через Edge Function с `service_role`;
- токен шифруется Edge Function через Web Crypto AES-GCM;
- ключ хранится в secret `COURSES_TOKEN_ENCRYPTION_KEY`;
- токен никогда не возвращается клиенту и не пишется в логи.

### 9.3. `course_study_plans`

```text
id uuid primary key
workspace_id text not null
created_by uuid not null
integration_id uuid not null
external_course_id text not null
external_release_id text not null
release_version integer
course_title text not null
course_cover_url text
course_accent_color text
start_date date not null
timezone text not null
weekday_times jsonb not null
excluded_dates date[] not null default '{}'
calendar_id text not null
responsible_id uuid
member_ids uuid[] not null default '{}'
reminder text not null default '1h'
status text not null default 'active'
idempotency_key text not null
last_synced_at timestamptz
created_at timestamptz
updated_at timestamptz
```

`status`:

- `active`;
- `completed`;
- `paused`;
- `disconnected`;
- `archived`.

### 9.4. `course_study_sessions`

```text
id uuid primary key
plan_id uuid not null
external_lesson_id text not null
external_module_id text
lesson_title text not null
module_title text
position integer not null
lesson_url text not null
scheduled_date date not null
start_time text not null
end_time text not null
duration_minutes integer not null
calendar_event_id text
status text not null default 'scheduled'
completed_at timestamptz
created_at timestamptz
updated_at timestamptz
```

`status`:

- `scheduled`;
- `completed`;
- `skipped`;
- `unscheduled`;
- `deleted`.

### 9.5. Связанное событие

Для каждого занятия создаётся `events`:

```text
title = "<Название курса> · <Название урока>"
date = course_study_sessions.scheduled_date
start_time = course_study_sessions.start_time
end_time = course_study_sessions.end_time
category = "education"
linked_entity_type = "course-lesson"
linked_entity_id = course_study_sessions.id
calendar_id = course_study_plans.calendar_id
responsible_id = course_study_plans.responsible_id
member_ids = course_study_plans.member_ids
reminder = course_study_plans.reminder
repeat = "none"
```

Каждый урок создаётся отдельным событием. Нельзя использовать одно повторяющееся событие, потому что у уроков разные названия, длительность, ссылки и статусы.

## 10. Серверные операции

### 10.1. Edge Function `courses-integration`

Одна Edge Function принимает действие:

```json
{
  "action": "connect | status | list-courses | manifest | create-plan | disconnect",
  "payload": {}
}
```

Функция:

- проверяет JWT календаря;
- проверяет доступ к workspace;
- получает и расшифровывает токен;
- вызывает API Courses;
- нормализует ошибки;
- не отдаёт секреты клиенту;
- использует timeout внешнего запроса;
- пишет безопасные структурированные логи без токена.

### 10.2. Создание плана

Создание плана, сессий и событий выполняется одной транзакционной RPC-функцией календаря:

```text
create_course_study_plan(...)
```

Операция должна:

1. Проверить пользователя и workspace.
2. Проверить `idempotency_key`.
3. Создать `course_study_plans`.
4. Создать все `course_study_sessions`.
5. Создать все `events`.
6. Записать `calendar_event_id`.
7. Вернуть план и созданные события.
8. Полностью откатиться при любой ошибке.

### 10.3. Изменение связанного события

При переносе события:

- обновить `course_study_sessions.scheduled_date`;
- обновить `start_time` и `end_time`;
- не менять порядок урока;
- не переносить остальные занятия автоматически.

При удалении события:

- установить `calendar_event_id = null`;
- установить `status = 'unscheduled'`;
- сохранить учебную сессию в плане;
- предложить пользователю запланировать её повторно.

При завершении события:

- установить `status = 'completed'`;
- установить `completed_at`;
- отправка прогресса обратно в Courses не входит в MVP.

Для надёжности связь поддерживается SQL trigger или отдельной транзакционной RPC. Нельзя полагаться только на браузерное событие `CALENDAR_LINK_CHANGE_EVENT`.

## 11. Управление учебным планом

На экране интеграции пользователь видит карточки активных планов:

- обложка и название курса;
- выполнено / всего;
- следующее занятие;
- дата завершения;
- состояние подключения.

Действия:

- открыть ближайший урок;
- показать расписание;
- перенести оставшиеся занятия;
- поставить план на паузу;
- продолжить план;
- архивировать;
- удалить будущие события;
- повторно создать незапланированные занятия.

### Пауза

В MVP пауза не удаляет будущие события автоматически. Пользователь выбирает:

- оставить даты;
- удалить будущие события и перепланировать позже.

### Отключение интеграции

Перед отключением показать выбор:

1. Отключить Courses и оставить события.
2. Отключить Courses и удалить будущие события.

Прошедшие события по умолчанию сохраняются.

## 12. Отображение в календаре

В карточке события показать бейдж:

```text
Курсы
```

В деталях события:

- название курса;
- модуль;
- название урока;
- длительность;
- позицию `Урок 4 из 18`;
- кнопку «Открыть урок»;
- ссылку на учебный план;
- состояние занятия.

Если Courses отключён, событие остаётся доступным, но кнопка открытия показывает понятное состояние переподключения.

Добавить:

```ts
COURSE_LESSON: 'course-lesson'
```

в `LINKED_ENTITY_TYPES`.

События курсов относятся к интеграциям и не должны скрываться переключателем дополнительных старых разделов.


Правила:

- Vue-компоненты используют Composition API и `<script setup lang="ts">`;
- API-запросы не выполняются из компонентов;
- расчёт расписания — чистая типизированная функция;
- серверное состояние загружается через TanStack Query;
- состояние шагов и полей формы остаётся локальным composable;
- существующую `IntegrationsPage.vue` не увеличивать новой бизнес-логикой;
- использовать существующие UI-компоненты календаря;
- не использовать нативные контролы, если в проекте уже есть готовый аналог;
- все даты вычислять с явным timezone;
- тексты ошибок должны быть понятны пользователю.

## 14. Безопасность и RLS

- Пользователь видит только свои подключения.
- План доступен только участникам соответствующего workspace.
- Создание событий разрешено только пользователю с правом создавать события.
- Токен Courses недоступен через Supabase REST.
- В логах нельзя сохранять токен, полный Authorization header и manifest целиком.
- URL урока считается внешним URL и проходит проверку допустимого origin.
- `course_title`, `lesson_title` и другие внешние строки должны безопасно отображаться без `v-html`.
- Все mutation-операции проверяют workspace на сервере.
- Отключение интеграции отзывает локальные credentials.
- Пользователю сообщается, что события в общем workspace видны его участникам.

## 15. Работа без сети

- Подключение, загрузка курсов и создание плана требуют сети.
- Мастер сохраняет незавершённые поля локально до закрытия модалки.
- После серверного создания плана календарь инвалидирует query событий.
- Нельзя оптимистично показывать план как созданный до подтверждения транзакции.
- Уже загруженные события продолжают работать через существующий offline-механизм календаря.

## 16. Обработка изменений курса

План закрепляется за `external_release_id`.

Если Courses сообщает о новой версии:

- существующий план не меняется;
- пользователь видит «Доступна новая версия курса»;
- переход на новую версию является отдельным будущим сценарием.

Если закреплённый release недоступен:

- существующие события сохраняются;
- интеграция показывает ошибку;
- новые занятия из этого release не создаются.

## 17. Нефункциональные требования

- Preview расписания до 500 уроков строится менее чем за 100 мс на клиенте.
- Создание плана до 200 уроков выполняется одной серверной операцией.
- Внешние вызовы имеют timeout и нормализованные ошибки.
- Повторный запрос с тем же `idempotency_key` безопасен.
- Модалка доступна с клавиатуры и корректно работает на мобильных экранах.
- Все новые функции планировщика покрыты unit-тестами.
- SQL-функция создания плана проверяется интеграционными SQL-тестами или диагностическим скриптом.

## 18. Тестовые сценарии

Обязательные сценарии:

1. Подключение с корректным токеном.
2. Ошибка при неверном токене.
3. Загрузка пустого списка курсов.
4. Курс с одним уроком.
5. Курс с разной длительностью уроков.
6. Планирование с одного выбранного дня недели.
7. Планирование с семи дней недели.
8. Дата начала совпадает с выбранным weekday.
9. Исключение даты из preview.
10. Конфликт с существующим событием.
11. Урок не помещается до полуночи.
12. Повторное подтверждение с тем же idempotency key.
13. Перенос одного созданного события.
14. Удаление одного созданного события.
15. Отключение с сохранением событий.
16. Отключение с удалением будущих событий.
17. Отозванный токен после ранее успешного подключения.
18. Недоступность Courses.
19. Недоступность закреплённого release.
20. Создание плана в общем workspace.

## 19. Критерии приёмки MVP

MVP считается готовым, если:

- пользователь подключает Courses персональным токеном;
- календарь показывает опубликованные доступные курсы;
- нельзя пропустить обязательный шаг мастера;
- расписание строится по выбранным дням до последнего урока;
- preview показывает все даты и дату окончания;
- подтверждение атомарно создаёт отдельные события;
- повторное подтверждение не создаёт дубликаты;
- каждое событие связано с конкретным уроком;
- из события можно открыть урок Courses;
- перенос события обновляет учебную сессию;
- удаление события не удаляет весь учебный план;
- токен не доступен браузеру после подключения;
- RLS не позволяет читать чужие планы и подключения;
- отключение интеграции предлагает сохранить или удалить будущие события;
- пройдены unit-тесты, `npm run test` и `npm run build`.

## 20. Не входит в MVP

- полноценный OAuth;
- автоматическое создание аккаунта Courses;
- запись прогресса из календаря обратно в Courses;
- realtime webhook о завершении урока;
- автоматическая миграция плана на новый release;
- интеллектуальный перенос занятий при конфликте;
- несколько уроков в один день;
- разные часовые пояса внутри одного плана;
- совместное прохождение одного курса несколькими пользователями;
- публичный каталог курсов внутри календаря;
- редактирование содержимого курса из календаря.
