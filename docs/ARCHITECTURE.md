# Архитектура клиентского приложения

## Разделение состояния

TanStack Query хранит только серверное состояние: коллекции Supabase, настройки workspace, журнал активности, административные счётчики и семейное дерево. Локальные настройки интерфейса, черновики форм, выбранные вкладки и offline-очередь остаются во Vue refs/localStorage.

Это разделение принципиально: Query отвечает за получение, кэширование и актуализацию данных сервера, а Vue — за состояние текущего интерфейса.

## Слои

1. `api/` выполняет один конкретный запрос и ничего не знает об интерфейсе.
2. `query/` содержит общий QueryClient и фабрики ключей кэша.
3. `repositories/` совмещает Query-кэш с offline-first поведением и очередью синхронизации.
4. `composables/` собирает запросы и доменные операции для страниц.
5. `components/` получает данные через props/composables и отправляет пользовательские события.
6. `pages/` компонует сценарий страницы, но не формирует SQL/Supabase-запросы.

## Структура по LIFT

- **Locate.** Общие форматтеры находятся в `utils/formatters/`, преобразование формы события — рядом с календарными компонентами в `components/calendar/eventFormMapper.js`, бюджетные правила — в `stores/budget/budget.helpers.js`, преобразование административных модалей — в `modules/admin/services/adminModalMapper.js`.
- **Identify.** Имя файла описывает одну ответственность: форматирование валюты, русское склонение, подготовка формы события или преобразование модального окна. Компоненту не нужно знать детали нормализации данных.
- **Flat.** Новые модули размещаются не глубже предметного раздела и не образуют цепочки папок с единственным файлом.
- **Try to be DRY.** Денежные значения, русские формы слов, бюджетные даты, данные событий и административных модалей нормализуются в одном месте и покрываются отдельными тестами.

Компоненты сохраняют UI-состояние и обработчики взаимодействия. Чистые вычисления и преобразования должны выноситься в именованный модуль, если используются повторно или мешают читать основной сценарий компонента.

## Правила разработки

- Не выполнять Supabase-запросы непосредственно из Vue-компонента.
- Все query keys создавать через `queryKeys`.
- После мутации обновлять кэш оптимистично либо инвалидировать минимальный ключ.
- Не помещать в Query состояние модальных окон, фильтров до применения и полей формы.
- Не дублировать серверные данные в новом глобальном store.
- Публичные функции и нетривиальные решения документировать на русском языке.
- Сохранять offline-очередь для пользовательских коллекций: Query не заменяет механизм гарантированной доставки изменений.

## Порядок безопасной миграции

Центральный `SyncedCollectionRepository` подключён к Query первым, поэтому большинство доменных модулей получают кэш без изменения публичного API. Экраны с прямыми запросами переносятся по одному в composables. Такой подход сохраняет обратную совместимость и позволяет проверять каждый сценарий отдельно.
