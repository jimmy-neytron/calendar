# Цены обычного магазина (на полке)

1. В базе с предыдущими миграциями выполнить
   `supabase/migrations/20260903020000_store_catalog_in_store_prices.sql`.
   Миграция обновляет проверку источников и сохранение снимка; сама не удаляет
   товары и не переводит существующие источники доставки в другой режим.
2. Развернуть `store-catalog-sync` вместе с локальными импортами:
   `supabase functions deploy store-catalog-sync --no-verify-jwt`.
3. Опубликовать фронтенд. Ссылки с `shopType=1` принимаются как
   «В магазине · Цены на полке»; `catalogType=1` можно не указывать.
4. Выключить автообновление у старых источников доставки. Добавить или
   отредактировать источники, вставив ссылки обычного магазина с сайта Магнита.
   Не заменять параметры доставки вручную без проверки выбранного магазина.
5. Нажать «Обновить сейчас». Удалять товары не требуется. При смене источника
   его старые цены теряют подтверждение; при сохранении снимка другой режим
   также исключается из подтверждённых цен. Меню и привязки сохраняются.

Контроль магазина и режима выполняется для каждого товара. Для обычного магазина
запрашиваются `storeType=1`, `catalogType=1`; ответ должен содержать тот же
`storeCode`, `service=core_mm` и `catalogType=1`. Доставка не используется как
резервный источник. Данные сайта могут отличаться от ценника и кассы.

# Управление источниками и очистка категории

Для удаления одного или нескольких товаров прямо из каталога дополнительно
выполнить `supabase/migrations/20260903010000_store_catalog_delete_products.sql`
и опубликовать фронтенд. Миграция сама ничего не удаляет. В «Товарах магазина»
можно удалить товар кнопкой корзины или выбрать несколько чекбоксами.
«Выбрать на странице» заменяет текущий выбор товарами показанной страницы.
«Выбрать все найденные» выбирает все результаты фильтра, включая другие страницы;
при сужении фильтра скрытые товары снимаются с выбора. Для старых остатков
есть фильтр «Без источника». Подтверждение показывает точный список к удалению.
Удаляются выбранные товары из всех источников, их история и привязки; меню,
рецепты и источники остаются. Обновление источника может вернуть товар,
но не его старые привязки. Во время синхронизации удаление блокируется.

Для базы с уже установленной поддержкой весовых товаров:

1. Выполнить в Supabase SQL Editor файл
   `supabase/migrations/20260902230000_store_catalog_source_management.sql`.
   Затем выполнить `supabase/migrations/20260903000000_store_catalog_source_delete_products.sql`.
   Если первая миграция уже применена, достаточно второй. Обе миграции только
   добавляют RPC, сами не удаляют товары или источники.
2. Развернуть обновлённую функцию командой
   `supabase functions deploy store-catalog-sync --no-verify-jwt`
   в связанном проекте. Проверка версии источника отменяет запуск, если между
   выбором источника и началом загрузки его изменили, очистили или удалили.
3. Опубликовать фронтенд. В «Питание → Закупка → Источники цен» доступны
   «Редактировать», «Удалить источник» и «Очистить товары категории».

По умолчанию удаление источника удаляет и его уникальные товары, их историю,
ручную фасовку и привязки ингредиентов. Общие товары других источников остаются.
В подтверждении можно снять галочку «Удалить также товары этого источника»,
чтобы сохранить все товары, историю и привязки. Цены удалённого источника
перестают считаться подтверждёнными. Обе операции выполняются атомарно.
Изменение только названия
не сбрасывает цены; изменение ссылки или магазина требует нового обновления.

Очистка удаляет товары, связанные только с выбранным источником, вместе
с историей цен, ручной фасовкой и привязками к ингредиентам. Товары других
источников сохраняются. Меню и рецепты не удаляются. Источник остаётся,
автообновление выключается. Затем нажать «Обновить сейчас» и заново
настроить привязки удалённых товаров; авто при необходимости включить вручную.
Для обычной актуализации цен очистка не нужна.

Действия требуют администратора, подтверждение удаления показывается в UI.
Во время синхронизации изменение и очистка источника запрещены.
Если миграция отсутствует, UI сообщает об этом и не изменяет локальные данные.

## Обновление поддержки весовых товаров

1. Выполнить в существующей базе миграцию
   `supabase/migrations/20260902220000_store_catalog_weighted_prices.sql`.
   Она добавляет поля веса и обновляет транзакционную функцию сохранения;
   товары, связи ингредиентов и история не удаляются.
2. Заново развернуть Edge Function `store-catalog-sync` вместе с её локальными
   импортами (`supabase functions deploy store-catalog-sync --no-verify-jwt` в связанном проекте,
   как в существующей конфигурации из README; сама функция проверяет JWT администратора).
3. Опубликовать обновлённый фронтенд.
4. Нажать «Обновить сейчас» у источников весовых товаров. Старый импорт содержал
   пустую цену: одного обновления страницы недостаточно.

Не запускать повторно первоначальную миграцию `20260902_store_catalog_v2.sql`:
она предназначена для первоначального создания каталога.

Проверка: у картофеля должны быть видны цена за весовую порцию, её вес и
цена за килограмм. Закупка округляется до шага заказа магазина, с учётом
минимума; окончательная сумма зависит от фактического взвешивания.
Ручная фасовка весовых товаров не применяется к цене магазинной порции.

Если новая функция запущена до миграции, синхронизация сообщит об отсутствующей
миграции; новый формат не должен молча сохраняться старой SQL-функцией.
